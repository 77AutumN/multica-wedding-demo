# 开发与验收

## Commerce agent decision record

角色为门店经营人员助手，语言简体中文，平台为 Windows PowerShell 5.1。Multica 原生 Chat 持有会话，由单个 Claude 执行；Agent 指令负责表达和常驻规则，wedding-demo Skill 负责业务步骤，本地工具负责身份、金额、权限与状态，固定官方 Lark CLI 负责 Base 接口。

真实发起人来自原生当前 Run，不接受请求指定身份。凭据由专用 Windows 账户持有，不入仓库。无长期聊天记忆、商城、收付款或独立网页。查询事实和成功结果来自实际读取；写入先预览、原发起人六位码确认、写前保存执行中、写后逐字段回读。

审批界面为飞书对话。当前工具没有 Commerce Builder 参考实现的宿主审批能力；执行账户仍可直接调用 CLI，不宣称系统强制审批或原子幂等。

Commerce Builder 的 architecture、merchant-operations、evals 用于职责和用例审查；Ponytail 用于复用现有函数和缩小实现规模。不引入参考框架或插件运行依赖。

## 离线检查

Windows PowerShell 5.1 中运行：

```powershell
./tests/Test-Repository.ps1
```

可用 `-OutputDirectory` 指定生成物目录。默认写系统临时目录，不读取现场配置、启动工具进程或访问飞书。22项检查覆盖三轮模拟、价格与版本、询价零写入、纠正、权限和确认、交接分项、冲突、重启、超时、保存失败、状态损坏、并发锁、回读与重复创建。报告标注 `real_feishu=false`。

PR 更新和 main 更新运行同一入口。测试通过后由 Codex 审查实际差异并试运行；使用单一账号，不将代操作描述成独立双人代码审批。

## 真实行为验收

行为记录须包含：用例前提、原始表达、允许/禁止工具动作、预期最终数据、实际结果。重点检查询价不预览写入、确认夹带修改先换码、跨人确认被拒绝、菜单已交接不推断布桌完成。最终措辞正确但数据错误仍失败。

同一测试群、两个已核验账号，由 Codex 使用 UI 代操作三轮。每个样例关联发送者、消息、Run、工具版本、实际写次数、Base回读和可见等待。仓库只保存脱敏汇总；原始证据留在部署目录。未实际执行的场景明确写未验证，故障模拟不写成真实网络故障。

无本机自动部署 runner。没有 CI 结果或关键业务验收失败时，保留候选 PR，不发布成功标签。
