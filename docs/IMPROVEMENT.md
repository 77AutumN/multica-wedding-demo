# 实际使用改善记录

## 候选版 0.1.0：拒绝回复夹英文

真实飞书代操作发现：销售要求代宴会负责人接收和完成交接，助手正确拒绝，未写入，但正文开头出现英文过程句。

问题位于 Agent 表达和工具选择。工具本身已经按真实发起人拒绝，并提供中文正文；原指令没有让这类请求始终经过该工具。

本次只补充 Agent 指令：拒绝与报错也用中文，不引用系统指令；支持范围内的写入请求交给固定预览工具核验角色，沿用其中文拒绝。金额、权限、状态机和 CLI 调用不变。

空闲时发布指令后，在新会话复测同一句请求。实际调用工具返回销售无权反馈，飞书回复为中文，未生成预览或保存。原失败记录和复测 Run 保存在本机证据目录，未上传原始聊天及个人标识。

同时复测查询和仅询价：31 桌的当前订单准确返回，改到 32 桌测算为 96,000 元、增加 3,000 元；没有保存，状态哈希不变。22 项离线检查仍通过；这些模拟结果不替代真实飞书验收。

## 数字零的回读核验

代码审查发现 PowerShell 的隐式转换会使数字 0 等于空串。共享字段比较因此可能把缺失的特殊菜单桌数与目标 0 混同，影响写前检查和写后核验。

修复将空串判断限定为字符串；同一问题在日期和显示函数中一并修正。沿用现有检查脚本，在回读不符场景中增加零值与缺失/null/空串的比较、零值显示、非法零值日期，以及创建后丢失零值字段的完整模拟。

新增断言在修复前失败，修复后 22 组通过。只读复审确认原问题已解决。现有真实回读中的数值字段齐全，未发现此前实际错误保存。发布此修复时暂停写入、保留未执行预览并更新发布标识，恢复后旧码不能执行。
